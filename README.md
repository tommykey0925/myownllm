# BungakuLLM — 日本文学で学ぶ言語モデル

青空文庫の日本文学作品（夏目漱石、太宰治、芥川龍之介など）を読み込んで、"それっぽい日本語の文章" を自動生成するAIを、ゼロから作るプロジェクトです。

**言語モデル**とは、「次に来る文字（単語）を予測する」ことで文章を生成するAIのことです。ChatGPTなどの大規模なものと同じ仕組み（**Transformer**）を、学習用に小さくしたものを自分で組み立てて動かせます。

---

## 使い方

### インストール

```bash
pip install -r requirements.txt
```

### 学習

```bash
python train.py
```

初回実行時、青空文庫から12作品（約120万文字）が自動ダウンロードされます。学習が終わると `checkpoint.pt` にモデルが保存されます。

### テキスト生成

```bash
# そのまま生成
python generate.py

# プロンプト（書き出し）を指定して生成
python generate.py --prompt "吾輩は" --max-tokens 300 --temperature 0.8
```

---

## 処理の流れ

このプロジェクトは **データ取得 → トークン化 → 学習 → 生成** の4ステップで動きます。

```
青空文庫12作品 → 文字を数値に変換 → 「次の文字を当てる」訓練 → 文章を1文字ずつ生成
```

---

### 1. データ取得（`train.py` — `load_data` 関数）

青空文庫（著作権切れの文学作品を無料公開しているサイト）から、以下の12作品を自動ダウンロードします:

> 坊っちゃん、吾輩は猫である、走れメロス、羅生門、蜘蛛の糸、銀河鉄道の夜、舞姫、こころ、三四郎、破戒、人間失格、斜陽

ダウンロード後、青空文庫特有のルビ（ふりがな）記号や注記を除去して、プレーンなテキストに整えます（`clean_aozora` 関数）。

こうして集めたテキストのことを**コーパス**（= モデルの学習に使うテキストデータのまとまり）と呼びます。

---

### 2. トークン化（`train.py` — `encode` / `decode`）

コンピュータは文字をそのまま扱えないので、すべての文字を数値（ID）に変換します。この変換を**トークン化**と呼びます。

```
"吾輩は" → [1532, 2801, 412]   （数値は例です）
```

本プロジェクトでは**文字レベル**のトークン化を採用しています。1文字 = 1トークンです。

- **語彙サイズ**（= テキストに登場するユニークな文字の数）は日本語だと約3,800文字になります（漢字・ひらがな・カタカナなど）。英語だと約65文字（a-z, A-Z, 記号など）で済むので、日本語のほうが語彙が大きいです。
- 実用的な大規模モデル（ChatGPTなど）では**サブワード**方式（BPE）を使い、「よく出る文字の並び」をまとめて1トークンにすることで効率を上げています。

---

### 3. モデル構造（`model.py`）

テキストを数値に変換したら、それを処理するモデル（ニューラルネットワーク）に渡します。ここでは各パーツを「何をしているか」の順に説明します。

#### 埋め込み — 数値をベクトルに変換（`Bungaku.__init__`）

文字IDのままだと「1532 と 1533 は似ている」のような意味のない関係が生まれてしまいます。そこで、各文字IDを**ベクトル**（= 256個の数値の並び）に変換します。この変換テーブルが**埋め込み（Embedding）**です。

学習を進めると、意味や使われ方が近い文字のベクトルは自然と近くなっていきます。

```python
self.token_emb = nn.Embedding(vocab_size, cfg.n_embd)  # 文字ID → 256次元ベクトル
```

さらに、**位置埋め込み**で「この文字は文中の何番目か」という情報も加えます。Transformerは文字の並び順を自動では認識できないため、位置情報を明示的に教える必要があります。

```python
self.pos_emb = nn.Embedding(cfg.block_size, cfg.n_embd)  # 位置 → 256次元ベクトル
```

#### Attention — どの文字に注目すべきかを学ぶ（`Head`）

「吾輩は猫**で**ある」の「で」を予測するとき、「猫」に強く注目し、「吾輩」にはそこそこ注目する——この「注目の度合い」を自動的に学ぶ仕組みが**Attention（注意機構）**です。

各文字から3種類の情報を作ります:

| 名前 | 役割 | 比喩 |
|------|------|------|
| **Query (Q)** | 「自分は何を探しているか」 | 質問 |
| **Key (K)** | 「自分はどんな情報を持っているか」 | 見出し |
| **Value (V)** | 「自分が提供する実際の中身」 | 答え |

QとKの相性が良いほど「注目度」が高くなり、そのぶんVの情報を多く受け取ります。

また、**因果マスク**によって「未来の文字を見てカンニングする」ことを防いでいます。文章生成時には未来の文字は存在しないため、学習中も未来を見ないようにします。

#### マルチヘッド Attention（`MultiHeadAttention`）

1つのAttentionヘッドでは「1つの視点」からしか注目パターンを学べません。そこで、複数のヘッドを並列に動かして、異なる視点（たとえば「文法的なつながり」と「意味的なつながり」）を同時に学習します。

本プロジェクトでは**8個のヘッド**を使い、それぞれが256 ÷ 8 = **32次元**を担当します。各ヘッドの出力を結合して元の256次元に戻します。

#### Feed-Forward Network（`FeedForward`）

Attentionが「文字同士の関係」を処理するのに対し、FFNは「各文字の情報そのものを加工・変換」するステップです。2層のニューラルネットワークで、一度4倍の1024次元に拡大してから元の256次元に戻します。

#### ブロック（`Block`）— 上記をまとめて繰り返す

Attention + FFN を1セットにしたものが**ブロック**です。本プロジェクトではこれを**6回**積み重ねます。層が深いほど、より複雑なパターン（文体、文法、意味）を学習できます。

各ブロックには2つの工夫が入っています:

- **残差接続**: 「元の情報 + 新しい情報」を足し合わせることで、層が深くなっても情報が失われにくくなります
- **LayerNorm**: データの値を一定の範囲に揃えて（正規化して）、学習を安定させます

---

### 4. 学習ループ（`train.py`）

学習は以下のサイクルを20,000回繰り返します:

1. テキストからランダムに一部を切り出す（**バッチ** = まとめて処理する単位。一度に64個の断片を処理）
2. 各文字について「次の文字」を予測する
3. 予測と正解のズレ（= **loss / 損失**）を計算する。lossは「モデルがどれだけ間違えたか」を表す数値で、これが下がるほどモデルが上達しています
4. ズレを小さくする方向にモデルの中身（パラメータ）を少しずつ修正する

パラメータの修正には**AdamW**という手法を使っています。これは文字ごとに「よく変わるパラメータはゆっくり」「あまり変わらないパラメータは大きく」と学習の速さを自動調整してくれる賢い仕組みです。

1,000ステップごとに、学習に使っていないテキスト（検証データ）でもlossを測定し、モデルが丸暗記（過学習）していないかチェックします。

---

### 5. テキスト生成（`generate.py`）

学習済みモデルを使って、1文字ずつ順番に予測して文章を組み立てます:

1. 最初の文字（またはプロンプト）をモデルに入力
2. モデルが「次に来そうな文字」の確率を出力
3. 確率に従って1文字を選ぶ
4. 選んだ文字を追加して、2に戻る

**temperature（温度）**パラメータで生成のバリエーションを調整できます:

| temperature | 効果 |
|-------------|------|
| 低い（例: 0.5） | 確率の高い文字ばかり選ぶ → 無難で安定した文章 |
| 1.0（デフォルト） | 元の確率分布どおり |
| 高い（例: 1.5） | 確率の低い文字も選ばれやすくなる → 意外性のある文章 |

## ファイル構成

| ファイル | 何をしているか |
|---|---|
| `config.py` | モデルの設定値（パラメータ）を一箇所にまとめて管理 |
| `model.py` | Transformerモデル本体（Head, MultiHeadAttention, FeedForward, Block, Bungaku） |
| `train.py` | データのダウンロード・トークン化・学習ループ・チェックポイント保存 |
| `generate.py` | 保存済みモデルを読み込んでテキスト生成するコマンドラインツール |
| `requirements.txt` | 必要なライブラリ（PyTorch, NumPy） |

---

## ハイパーパラメータ

| パラメータ | 値 | 何を決めているか |
|---|---|---|
| `n_embd` | 256 | 各文字を表すベクトルの大きさ。大きいほど表現力が増すが、計算も重くなる |
| `n_head` | 8 | Attentionの「視点」の数。多いほど多角的に注目できる |
| `n_layer` | 6 | ブロックの積み重ね回数。深いほど複雑なパターンを学べる |
| `block_size` | 128 | 一度に見られる最大文字数（コンテキスト長） |
| `dropout` | 0.1 | 学習中にランダムに10%の情報を捨てることで、丸暗記（過学習）を防ぐ |
| `batch_size` | 64 | 1ステップでまとめて処理するテキスト断片の数 |
| `learning_rate` | 3e-4 | パラメータを1回の修正でどれだけ動かすか。大きすぎると暴走、小さすぎると学習が遅い |
| `max_iters` | 20,000 | 学習を繰り返す回数 |
| `eval_interval` | 1,000 | 何ステップごとに検証データでチェックするか |
| `eval_iters` | 200 | 検証時に使うバッチの数（多いほど正確だが時間がかかる） |
